# Git Lesson

## リモートリポジトリとローカルリポジトリとはそれぞれ何でしょうか？
* リモートリポジトリはネットワーク上にあり、    チーム全体のソースコードやコミットを共有、管理する場所
* ローカルリポジトリは自分のPC上で作成されるGitのリポジトリで、ソースコードやコミットをした変更内容を保存、管理する場所


## プッシュとマージの違いは何でしょうか？
* プッシュはローカルリポジトリで記録したものをリモートリポジトリにアップロードして同期する操作のこと
* マージは枝分かれしたブランチ同士を１つのブランチに合流させて、変更内容を統合する操作のこと


## コミットとプッシュの違い
* コミットは自分のPC内で作業し変更した内容を記録すること
* プッシュはローカルリポジトリで記録したものをリモートリポジトリにアップロードして同期させること


## コミットのメッセージはどのように書いてあげるのが最適でしょうか？
* 誰が見ても変更した箇所がわかるように記載する


## ローカルでマージするフローと、プルリクエストでマージするフローの違いは何でしょうか？
* ローカルでマージする時は自分だけで修正したものをローカルのmainブランチに直接統合してしまうため、エラーなどに気づきにくい、そのまま本番や共有ブランチに反映されるリスクがある
* プルリクエストでマージする時は自分で修正した内容をレビュー担当者に確認してもらうため、ミスなどに気づきやすい。最終的なマージ作業は、基本的にはレビュー担当の人が行う


## コンフリクトを起こしてしまった場合、どう対処すべきですか？
相手のコードを優先したり、自分のコードが正しければ相手のコードに上書きしたり、自分のコードと相手のコードの変更内容を取り込んだりする（よくわからないコードにぶつかったら自分で判断せず、そのコードを書いた人に相談もする）
相手のコードを優先する判断基準：相手のコードの方が最新の仕様を満たしている場合や、自分の修正が不要になったという判断をしたとき
自分のコードを優先する判断基準：相手のコードが古い仕様のままで、自分のコードの方が確実に最新かつ正しい実装であると判断したとき
両方の変更内容を取り込むときの判断基準：相手の修正と自分の修正がどちらもシステムに必要である場合や両方生かすべきと判断したとき
